## 작업 환경이 두 곳 (가장 먼저 읽을 것)

| | 로컬 PC | 클라우드 세션(휴대폰 등) |
|---|---|---|
| 고치는 곳 | `src/` 모듈 → `python build.py` → `docs/index.html` 생성 | `docs/index.html`을 직접 고침 |
| 볼 수 있는 것 | 폴더 전체 | 저장소에 올라간 `docs/`·`notes/`·`.gitignore`만 |
| 노트 | `notes/` (같은 파일) | `notes/` (같은 파일) |

- `src/`·`build.py`·`tools/`·`tests/`·`CLAUDE.md`·`설계.md`는 저장소에 올리지 않는다(2026-07-21 결정: 소스는 공개하지 않음). 그래서 클라우드에서 고친 내용은 로컬 `src/`에 저절로 반영되지 않는다.
- 실제로 v137~v170은 클라우드에서 배포됐고, 2026-11-10에 로컬에서 배포본 v170을 `src/`로 다시 나눴다.
- 지킬 것
  1. **클라우드에서 앱을 고치면** 같은 커밋에 `notes/작업노트.md` 항목을 더한다. 로컬은 이 기록을 보고 따라온다.
  2. **로컬에서 작업을 시작할 때** `git fetch` 뒤 `origin/main`의 `docs/index.html` 안 `APP_VERSION`과 `src/00_config.js`의 값을 견준다. 다르면 클라우드에서 배포된 것이므로 배포본에서 `src/`를 다시 나눈 뒤 작업한다.
  3. **`tools/port_clock.py`는 돌리지 않는다.** `src/15_clock.js`는 클라우드에서 직접 고쳐져 이제 손으로 고치는 소스다. 생성기를 돌리면 그 변경이 지워진다.
  4. **로컬에서 `git add -A`와 `배포.bat`을 쓰지 않는다.** `docs/코드지도.md`(로컬 전용, 저장소에 없음)가 배포 폴더 안에 있어 함께 공개된다. `git add docs/index.html notes/`처럼 파일을 지정한다.
  5. 배포(push)는 **사용자 확인을 받은 뒤**에만 한다. 빌드·검증까지 하고 묻는다.

### 힌트 공통 문법 (새 힌트를 만들 때)

- 모형은 해당 숫자 아래에 매단다(절대 배치 — 수식 배치·간격은 움직이지 않는다).
- 이어 세기: 앞 수에 빨간 동그라미를 치고 시작값을 말한 뒤 이어 센다.
- 일의 자리부터(받아올림·받아내림 대비).
- 올림 = 낱개 10 → 막대로 변신, 내림 = 막대 → 낱개 10.
- 자리 계산이 끝날 때마다 정답 칸의 그 자리를 채우고 진행 카운터를 올린다.
- 애니메이션 끝 상태는 `setTimeout`으로 확정한다(`onfinish`는 백그라운드 탭에서 안 온다). 사라지거나 도착할 대상은 시퀀스를 만들 때 미리 정한다(실행 중 DOM 검색은 타이밍이 어긋난다).
